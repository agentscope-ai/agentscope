# AgentScope Desktop

AgentScope Desktop packages the Web UI and a local AgentScope backend into one
application for macOS, Windows, and Linux. Release builds include Python,
AgentScope, SQLite, and Qdrant Local; end users do not need to install Python
or Redis.

## Development

Install the Python, Web UI, and desktop dependencies from the repository root:

```bash
python -m pip install -e ".[desktop-build]"
pnpm --dir examples/web_ui install --frozen-lockfile
pnpm --dir apps/desktop install --frozen-lockfile
```

Run Electron with the Python interpreter from the active environment:

```bash
cd apps/desktop
AGENTSCOPE_PYTHON="$(command -v python)" pnpm electron:dev
```

On Windows PowerShell, set the executable explicitly:

```powershell
cd apps/desktop
$env:AGENTSCOPE_PYTHON = (Get-Command python).Source
pnpm electron:dev
```

The development backend still runs from source, but it uses the same SQLite,
authentication, port-handshake, and process-lifecycle paths as a packaged app.

## Build

Build the backend and the current platform's installer:

```bash
cd apps/desktop
pnpm electron:build
```

Build an unpacked application for a faster smoke test:

```bash
cd apps/desktop
python build_backend.py
pnpm electron:pack
```

Generated backend, frontend, and installer artifacts are ignored by Git.
PyInstaller output is written under `apps/desktop/dist`, and Electron Builder
output is written under `apps/desktop/dist-electron`.

CI builds unpacked applications without code signing so they can be used for
cross-platform smoke validation. Installers distributed to end users must be
signed on Windows and signed and notarized on macOS using release credentials
provided outside the repository.

## Local data

Electron passes its platform-native `userData` directory to the backend. It
contains:

```text
agentscope.db
workspaces/
qdrant/
blobs/
```

The backend listens only on an ephemeral loopback port. Every normal request
must include the random bearer token generated by Electron for that launch.

## Knowledge bases

Desktop knowledge bases persist metadata in SQLite, vectors in Qdrant Local,
and uploaded source files in the local blob directory. Creating a knowledge
base still requires a configured embedding-model credential.

The desktop dependency set supports the default text parser. PDF, Word,
Excel, PowerPoint, image, and audio parsing are not bundled. Qdrant Local is
suited to small, single-user collections; the Electron application enforces a
single running instance so concurrent processes do not share its data path.
Use a server deployment for larger or shared knowledge bases.
