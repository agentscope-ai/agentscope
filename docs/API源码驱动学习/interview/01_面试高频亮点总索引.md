# 面试高频亮点总索引

> 用途：这份文档不是重复接口说明，而是把 AgentScope 最容易在面试里被追问的“产品流程 + 源码机制 + 系统设计亮点”集中成入口。阅读时建议先看本索引，再进入对应专题文件深挖。

---

## 1. 先给面试官的总表达

AgentScope 的核心价值不只是“能调用大模型聊天”，而是把 Agent 产品工程化成一套可恢复、可中断、可计划、可协作、可接知识库、可做人工确认、可观测、可扩展的运行系统。

可以这样说：

```text
这个项目把一次聊天拆成 Session 运行态、Agent Runtime、Toolkit、MessageBus、事件流和前端投影。
用户输入不是直接同步等待结果，而是触发一次可恢复的异步 run。
模型在 ReAct 循环里根据工具 schema 决定是否调用 Plan、Team、RAG、Workspace、TTS、ToolStop 等能力。
工具调用再经过权限引擎、HITL、后台任务、事件回流和状态持久化，最后通过 Web UI 呈现成完整产品流程。
```

## 4. 面试表达模板

### 一句话版

AgentScope 的设计亮点在于：它把 Agent 从一次 LLM 调用升级成了一个带状态、工具、权限、事件、计划、多智能体、RAG、TTS、后台任务和可观测性的异步运行系统。

### 3 分钟版

```text
用户在 Web UI 里发送消息后，前端不是同步等待完整回答，而是触发后端 ChatService.run。
后端根据 Session 配置装配模型、workspace 工具、Plan 工具、Team 工具、RAG 中间件、TTS 中间件、权限上下文和后台任务能力。
Agent Runtime 进入 ReAct 循环：先 reasoning，让模型基于上下文和工具 schema 决定下一步；如果产生 tool call，就进入 acting。
acting 前会经过 PermissionEngine，可能直接执行、拒绝，或发出 RequireUserConfirmEvent 等待人类确认。
长耗时工具会被 ToolOffloadMiddleware 转成后台任务，完成后通过 inbox+wakeup 回灌。
模型能力通过 ModelCard 暴露给前端，决定上传类型、thinking 参数和 voice 参数。
执行过程中模型输出、工具调用、工具结果、HITL、TTS 音频、状态更新都会形成事件流，前端通过 SSE 和 CustomEvent 投影成聊天消息、任务面板、团队侧栏、确认卡片和音频播放。
TracingMiddleware 再把 Agent、LLM、Tool 调用拆成 OpenTelemetry span，测试体系则按能力分层证明这些链路可靠。
```

## 5. 最容易被追问的点

| 追问 | 回答方向 |
|---|---|
| 有没有专门的意图识别模型？ | 没看到独立 classifier。源码里主要是 ReAct + 工具 schema/description + tool_choice + middleware 共同影响模型选择。 |
| Plan 是什么时候打开的？ | Plan 不是前端开关，而是 TaskCreate/TaskUpdate 等工具始终装配，模型在复杂任务中主动调用。 |
| 多 Agent 是不是进程内 new agent？ | 不是简单内存对象协作，而是 TeamRecord + SessionRecord + MessageBus + wakeup。成员有独立 session，可恢复和投影。 |
| RAG 是上传后立即可搜吗？ | 不是。上传登记文档和 blob 后入队索引任务，后台 worker 解析、分块、嵌入、写向量库，前端轮询状态。 |
| 权限怎么避免模型乱执行危险操作？ | Tool call 先经过 PermissionEngine，ASK 会停在 HITL，用户确认后把 UserConfirmResultEvent 喂回 Chat。 |
| 长任务上下文爆了怎么办？ | Agent 有上下文压缩机制，超过 trigger_ratio 后保留近期消息，把旧上下文压成结构化 summary，并用 shield 保护状态更新。 |
| 长耗时工具会卡住 Agent 吗？ | 超时后 ToolOffloadMiddleware 把工具放后台跑，Agent 立刻拿到占位结果；完成后 inbox+wakeup 通知。 |
| 怎么知道模型支持图片/音频？ | 后端 ModelCard 声明 input_types/output_types，前端根据 selectedModelCard 限制上传和参数展示。 |
| TTS 为什么能和文本一起流式回来？ | TTSMiddleware 把文本事件转换成音频 DataBlock 事件，复用同一条 SSE 事件流。 |
| Agent 怎么做 tracing？ | TracingMiddleware 创建 invoke_agent、chat、execute_tool span，并记录 session_id、reply_id、HITL pending 工具和 token usage。 |
| 怎么证明这些链路可靠？ | 看测试地图：模型、formatter、runtime、权限、HITL、MessageBus、RAG、Team、Workspace、TTS、Tracing 都有对应测试。 |
| Stop 按钮背后有什么设计？ | 202 异步控制命令、running/parked 分路、跨进程广播、asyncio 协作式取消、ReplyEnd SSE 收尾。 |
| 前端为什么复杂？ | 它要把历史消息、SSE 增量、HITL、interrupt、音频和多 Agent 投影合成一个可恢复状态机。 |
| 删除 Session 为什么复杂？ | 因为要先 cancel 运行，再删持久化记录和 Team/Schedule 级联，最后清理事件日志、inbox、后台任务 registry。 |
| AGUI 适配的价值是什么？ | 把内部 AgentEvent 转成外部协议事件，同时用 CustomEvent 保留 HITL、DataBlock 等 AgentScope 扩展能力。 |
| RAG 向量库怎么做到可替换？ | 上层依赖 VectorStoreBase，底层适配 Qdrant、MongoDB Vector Search、Milvus Lite。 |
| 知识库上传为什么要轮询？ | 文件上传完成不等于索引完成，后端还要解析、分块、embedding、写向量库。 |
| RAG Worker 崩溃怎么办？ | 文档处理有 lease 和 heartbeat；lease 过期后 Sweeper 会重新入队，其他 Worker 接管。 |
| AgentCreate 和 AgentInvite 最大区别？ | AgentCreate 创建 team-owned 临时 worker；AgentInvite 只给已有 Agent 创建 team-scoped session。 |
| MessageBus 为什么有这么多 key？ | 因为 replay log、pub/sub、queue、registry、lock 解决的是不同通信语义，不能混成一种。 |
| Chat 前端为什么要先拉历史再开 SSE？ | 历史负责恢复，SSE 负责实时；刷新到 running/HITL 时也能恢复正确 phase。 |
| 生产部署为什么要独立 IndexWorker？ | 文档解析和 embedding 可能耗 CPU、耗外部 API quota，独立 Worker 可以单独扩缩容。 |
| Parser 和 Chunker 为什么分开？ | Parser 保留文件自然结构，Chunker 控制检索粒度，避免每种格式重复实现分块。 |
| TeamSay 是同步调用另一个 Agent 吗？ | 不是。TeamSay 写目标 session 的 inbox，再 enqueue wakeup，目标 session 自己运行。 |
| Workspace 和 Permission 的区别？ | Workspace 决定工具在哪里执行，Permission 决定工具能不能执行。 |
| HITL 的规则如何持久化？ | 用户确认 suggested_rules 后，Agent 会把规则加入 `AgentState.permission_context`。 |
| 为什么要做故障演练？ | Agent 系统最容易出错的是异步恢复边界，必须覆盖断线、取消、worker 崩溃、HITL 恢复等场景。 |
| Formatter 解决什么问题？ | 它把内部统一 Msg/Block 转成各模型厂商自己的 messages、parts、tool_call、thinking 和多模态格式。 |
| 长期记忆和 RAG 有什么区别？ | RAG 查上传文档；长期记忆记住用户偏好、历史决策和跨会话事实。 |
| 定时任务为什么默认 DONT_ASK？ | 定时触发时没有用户在线，ASK 会悬挂，所以需要把 ASK 转成 DENY。 |
| shared credential 会泄露吗？ | UI view 会脱敏，只保留 type/name；只有 trusted runtime path 才能 resolve raw credential。 |
| 文档怎么变成面试材料？ | 每个模块整理成一句话、3 分钟回答、流程图、源码证据、追问、trade-off、测试证据和简历表达。 |
| 前端为什么把选择态放在 URL？ | agent/session/member 用 URL 表示，刷新、分享、前进后退都能恢复。 |
| schema-driven form 的价值是什么？ | 后端 Pydantic schema 是单一真相来源，前端动态渲染表单，减少字段漂移。 |
| message 为什么 upsert 而不是纯 append？ | 流式回复会更新同一个 message，最后一条同 id 时覆盖可避免重复历史。 |
| BlobStore 为什么独立于 Storage？ | Storage 存元数据和状态，BlobStore 存原始 bytes，两者生命周期和后端形态不同。 |
| 面试白板题怎么答？ | 先定位用户动作，再串 Web UI、HTTP、Service、MessageBus、Runtime、Storage 和事件回流。 |
| 异步系统怎么补测试？ | 用 Event/Queue 控制 race，重点测取消、lease、重复投递、SSE 顺序和状态收尾。 |
| AgentScope 的容量单位是什么？ | 不是普通 QPS，而是活跃 Agent run、SSE 长连接、工具耗时、RAG worker 和队列积压。 |
| 二次开发应该改源码还是用扩展点？ | 优先用 create_app 注入 Storage、MessageBus、Tool、Middleware、Parser、Chunker、Policy 等扩展点。 |
| 生产事故怎么排查？ | 从用户症状出发，沿 Web UI、API、Service、MessageBus、Storage、Runtime、后台组件逐层定位。 |
| 源码学习怎么坚持？ | 每天围绕一个产品动作产出源码入口、流程图、设计权衡、面试一句话和追问。 |

| RAG 质量怎么评估？ | 先评估检索 Recall@K、Precision@K、MRR，再评估答案正确率和引用准确率。 |
| 源码项目怎么包装成简历？ | 不夸大“独立实现框架”，而是讲基于源码做企业 Agent 工作台方案设计和二次开发能力。 |
