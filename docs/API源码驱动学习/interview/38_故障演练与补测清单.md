# 故障演练与补测清单

> 适合面试表达的关键词：故障注入、恢复路径、测试缺口、回归用例、生产演练、端到端验证。

---

## 1. 结论先行

AgentScope 这种 Agent 产品最容易出问题的地方，不是单个 CRUD，而是跨进程、跨状态、跨前后端的异步链路：

```text
Chat run 中断
SSE 断线重连
HITL parked 恢复
RAG Worker 崩溃
MessageBus 信号丢失
Team worker 删除
Workspace 权限误放行
前端状态机卡住
```

所以学习源码时，最后一定要补一份“故障演练与补测清单”。这能让面试表达从“我读过源码”升级成“我知道如何证明它可靠”。

---

## 2. 演练总表

| 模块 | 故障 | 预期恢复 |
|---|---|---|
| Chat | run 过程中进程崩溃 | session lock TTL 过期，前端不应永久 running |
| SSE | 网络断开 | 重新拉 messages + 重新订阅 stream |
| Interrupt | ReplyEndEvent 丢失 | 前端 10 秒 timeout 回 idle |
| HITL | 页面刷新时停在 asking | 前端从 tail tool_call 恢复 streaming |
| RAG | Worker 崩溃 | lease 过期，Sweeper 重新入队 |
| RAG | upload 后 signal 丢失 | pending_grace 后 Sweeper 重新入队 |
| Team | worker session 删除 | leader projection 清理，team 不应整体解散 |
| Permission | dangerous bash | bypass-immune ASK 或 DONT_ASK 转 DENY |
| Workspace | 写出工作目录 | ACCEPT_EDITS 不应自动允许 |

## 3. Chat / SSE 演练

### 3.1 SSE 断线重连

演练：

```text
1. 启动一次长回复。
2. 手动断开前端 SSE。
3. 刷新页面。
```

预期：

```text
1. 前端先 GET /sessions/{sid}/messages。
2. 根据 is_running 或 tail pending tool_call 恢复 phase。
3. 再打开 SSE。
4. 不重复渲染已持久化消息。
```

建议补测：

```text
前端 hook 层测试：history messages + is_running=true 时 phase=streaming。
前端 hook 层测试：tail asking tool_call 时即使 is_running=false，也 phase=streaming。
```

### 3.2 interrupt 收尾丢失

演练：

```text
1. phase=streaming。
2. 点击 Stop。
3. 模拟后端没有发 ReplyEndEvent。
```

预期：

```text
1. phase 进入 interrupting。
2. 10 秒后自动回 idle。
3. 不允许 Stop 按钮永久 disabled。
```

建议补测：

```text
useMessages interrupt timer 测试。
```

## 4. HITL 演练

### 4.1 普通 HITL 刷新恢复

演练：

```text
1. 工具调用触发 RequireUserConfirmEvent。
2. 前端显示 ConfirmCard。
3. 刷新页面。
```

预期：

```text
1. 历史消息中最后一条 assistant message 保留 asking tool_call。
2. 前端恢复 streaming。
3. ConfirmCard 仍可确认。
```

建议补测：

```text
event_to_message 已覆盖事件到消息状态转换。
还可以补前端端到端测试：刷新后确认卡仍可提交。
```

### 4.2 过期确认事件

演练：

```text
1. 构造 UserConfirmResultEvent。
2. tool_call id 不属于当前 awaiting_confirmations。
```

预期：

```text
Agent._check_incoming_event 抛错，不错误恢复别的工具。
```

## 5. RAG Worker 演练

### 5.1 Worker 处理中崩溃

演练：

```text
1. 文档进入 parsing/indexing。
2. 杀掉 Worker。
3. 等待 lease 过期。
4. Sweeper 重新入队。
```

预期：

```text
1. 新 Worker acquire lease。
2. 文档最终 ready 或 error。
3. 不重复写入两份 chunk。
```

建议补测：

```text
模拟 heartbeat 失败后 pipeline 被取消。
模拟 expired lease 被 sweeper re-enqueue。
```

### 5.2 上传后入队信号丢失

演练：

```text
1. 上传记录已保存为 pending。
2. 模拟 enqueue 或 signal 失败。
3. 等待 pending_grace。
```

预期：

```text
Sweeper 发现 orphan pending 并重新 enqueue_index_task。
```

## 6. Team / 多智能体演练

### 6.1 删除 worker session

演练：

```text
1. leader 创建 team 和 worker。
2. 直接删除某个 worker session。
```

预期：

```text
1. team 不应整体解散。
2. leader session 保留。
3. 该 worker 的 subagent HITL projection 被清理。
```

已有证据：

```text
tests/storage_redis_test.py 中有 direct delete worker session 不解散 team 的测试。
```

### 6.2 删除 leader session

预期：

```text
leader session 是 team 生命周期边界，删除它会解散 team。
```

## 7. Workspace / Permission 演练

### 7.1 ACCEPT_EDITS 写出工作目录

演练：

```text
1. PermissionMode=ACCEPT_EDITS。
2. Bash/Write/Edit 尝试修改 working_directories 外路径。
```

预期：

```text
不自动允许，进入 ASK 或 DENY。
```

### 7.2 dangerous bash

演练：

```text
rm -rf /
命令替换 $(rm -rf /)
写 ~/.bashrc
删除 ~
```

预期：

```text
DEFAULT / ACCEPT_EDITS：bypass-immune ASK。
DONT_ASK：ASK 转 DENY。
```

已有证据：

```text
tests/builtin_bash_test.py
tests/permission_bash_parser_test.py
```

## 8. 前端补测优先级

当前文档分析里，前端状态机很关键，建议补测试优先级如下：

| 优先级 | 测试 |
|---|---|
| P0 | `useMessages` 刷新到 `is_running=true` 时 phase=streaming |
| P0 | tail asking tool_call 时 phase=streaming |
| P0 | interrupt 10 秒 timeout 回 idle |
| P1 | CustomEvent `subagent_require_user_confirm` 去重 |
| P1 | `subagent_user_confirm_result` 清理卡片 |
| P1 | audio DataBlock start/delta/end 调用 audioManager |
| P2 | requestAnimationFrame 合并多次 SSE delta |

## 9. 后端补测优先级

## 10. 面试沉淀

### 一句话回答

我会围绕异步 Agent 系统最容易出错的链路做故障演练：Chat/SSE/HITL/RAG Worker/Team/Permission/Workspace，并用补测清单证明这些恢复路径是可验证的。

### 3 分钟讲解版

```text
AgentScope 的可靠性不能只看单元函数，要看跨前后端异步链路。
我会优先演练几类故障：
第一是 Chat 和 SSE，断线后要能通过历史消息和 replay 恢复，interrupt 丢 ReplyEndEvent 时前端要有 timeout 兜底。
第二是 HITL，工具停在 asking 后刷新页面仍要能确认，过期确认事件不能恢复错误 tool_call。
第三是 RAG Worker，处理中崩溃后 lease 过期，Sweeper 重新入队，其他 Worker 接管。
第四是 Team 生命周期，删除 worker session 不应解散 team，删除 leader session 才解散。
第五是 Workspace 和 Permission，Accept Edits 不能写出工作目录，危险 Bash 必须 ASK 或在 DONT_ASK 下 DENY。
这些演练对应的测试能把源码理解变成工程可靠性证据。
```

### 高频追问

| 追问 | 回答方向 |
|---|---|
| Agent 系统最该测什么？ | 测异步边界：断线、取消、恢复、worker 崩溃、权限暂停。 |
| 为什么 CRUD 不是重点？ | CRUD 风险相对低，跨状态链路才容易产生不一致。 |
| 如何证明 RAG 索引不丢？ | pending record + durable queue + lease + sweeper。 |
| 如何证明 HITL 可恢复？ | tool_call.state=asking 持久化，确认事件校验 id 后恢复。 |
| 前端最怕什么？ | phase 卡住、重复消息、确认卡丢失、SSE 断线后状态错误。 |

### 项目表达

```text
我不只看 AgentScope 的正常链路，也整理了故障演练和补测清单。重点覆盖 SSE 断线、interrupt 收尾丢失、HITL 刷新恢复、RAG Worker 崩溃、Team 删除级联、Workspace 越权写入和危险 Bash 操作。这些场景能证明系统在异步、分布式和人机协作边界上的可靠性。
```
