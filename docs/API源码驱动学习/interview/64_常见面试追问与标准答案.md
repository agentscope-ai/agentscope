# 常见面试追问与标准答案

> 适合面试表达的关键词：标准答案、追问、系统设计、源码证据、临场回答、STAR。

---

## 1. 使用方式

这份文档不是让你逐字背诵，而是训练回答结构：

```text
1. 先一句话定性。
2. 再讲产品链路。
3. 再补源码证据。
4. 最后讲 trade-off、边界和测试。
```

面试里最怕的是只答一个函数名。你要把每个问题都拉回：

```text
Web UI -> HTTP API -> Service -> MessageBus -> Agent Runtime -> Storage -> SSE 回流
```

## 2. Chat / Interrupt

### Q1：用户点击 Stop 后发生什么？

标准答案：

```text
Stop 是一个异步控制命令，前端在 streaming phase 调用 interrupt API，后端返回 202 表示命令已接受。running session 会通过 CancelDispatcher 取消正在运行的 asyncio task；parked HITL session 没有可取消 task，所以会注入 resume interrupt，让 Agent 恢复后短路收尾。最后通过 finally 清理状态，并通过 SSE 发布终态，前端回到 idle。
```

加分点：

```text
202 Accepted、幂等、running/parked/idle 三态、CancelledError、finally、shield、SSE reply_end。
```

追问：

| 追问 | 回答 |
|---|---|
| 为什么不是 200？ | 取消不是同步完成，HTTP 只表示命令被接受。 |
| 重复点击怎么办？ | API 保持幂等，前端 interrupting 状态禁用 Stop。 |
| idle session interrupt 怎么办？ | 对存在 session 是 no-op，不破坏状态。 |

## 3. SSE / 事件流

### Q2：为什么 Chat 触发和 SSE 订阅要分开？

标准答案：

```text
触发 run 和接收事件是两个不同平面。POST /chat 负责控制面，只触发后台 run；GET /sessions/{sid}/stream 负责数据面，接收 reply_start、delta、tool_call、state_updated、reply_end 等事件。这样可以支持断线重连、事件回放、多个订阅者和更清晰的状态机。
```

加分点：

```text
事件溯源、replay log、live pub/sub、前端 useMessages 合成状态。
```

## 4. RAG / 知识库

### Q3：上传知识库文档后为什么不能立刻检索？

标准答案：

```text
上传只完成原始 bytes 和 document record 的持久化，真正的解析、分块、embedding 和写向量库由 IndexWorker 异步完成。文档状态会从 pending 进入 parsing、chunking、indexing，最后变成 ready 或 error。这样避免大文件解析和 embedding 阻塞 API。
```

加分点：

```text
BlobStore、KnowledgeDocumentRecord、index queue、lease、heartbeat、polling。
```

### Q4：Parser 和 Chunker 为什么分开？

标准答案：

```text
Parser 负责把 PDF、Word、Excel、图片等不同格式解析成统一 Section，并尽量保留标题、页码、表格、sheet 等结构信息；Chunker 负责把 Section 切成检索粒度。两者分开后，可以复用解析结果并独立优化召回质量。
```

## 5. Plan / 多 Agent

### Q5：Agent 什么时候应该开启 Plan？

标准答案：

```text
当任务多步骤、有依赖、需要持续跟踪或可能由多个工具/多个 Agent 协作完成时，就适合开启 Plan。Plan 在 AgentScope 里不是前端 TODO，而是 Agent 通过 TaskCreate、TaskUpdate 等工具维护的运行态任务图，前端通过 state_updated 事件展示。
```

### Q6：多 Agent 是不是直接内存调用？

标准答案：

```text
不是。多 Agent 更像多个 session 的协作拓扑。leader 创建 worker 后，worker 有自己的 agent、session、state 和权限上下文；它们通过 TeamSay、MessageBus 和事件投影通信。这样才能支持隔离、恢复、审计和前端切换。
```

## 6. HITL / 权限

### Q7：HITL 确认后怎么恢复？

标准答案：

```text
工具调用需要用户确认时，Agent 进入 parked 状态并发出 RequireUserConfirmEvent，前端显示 ConfirmCard。用户确认后，结果作为 resume trigger 入队，WakeupDispatcher 恢复对应 session，并把确认结果交回 Agent 继续执行。resume trigger 携带用户结果，不能像普通 wake 一样随便丢。
```

### Q8：ASK / ALLOW / DENY 怎么理解？

标准答案：

```text
ALLOW 表示直接执行，DENY 表示直接拒绝，ASK 表示需要用户确认。定时任务无人值守时不能等待用户，所以通常需要把 ASK 降级为 DENY 或使用预授权规则。
```

## 7. Storage / MessageBus

### Q9：MessageBus 在系统里承担什么？

标准答案：

```text
MessageBus 不只是 pub/sub，它同时承担事件日志、实时订阅、队列和分布式锁。SSE 需要 event log 和 live pub/sub，wakeup 和 index task 需要 queue，同一 session 的 run 需要 lock 保证不并发执行。
```

### Q10：为什么 message 要 upsert 而不是纯 append？

标准答案：

```text
流式回复会不断更新同一个 assistant message。如果每个 delta 都 append，会产生大量重复历史。RedisStorage 里如果最后一条消息 id 相同，就覆盖最后一条；否则才追加。
```

## 8. 企业化 / 成本 / 测试

### Q11：企业多租户怎么改？

标准答案：

```text
底层继续保持 owner-scoped storage，以 user_id 做隔离。跨用户共享通过 ResourceAccessPolicy 显式返回 ResourceRef，区分 READ 和 EDIT。API view 带 editable，credential view 必须脱敏。工具权限再通过 PermissionContext 和 middleware 控制。
```

### Q12：模型成本怎么控制？

标准答案：

```text
单次 reply 可以用 ReplyBudgetControlMiddleware 监听 ModelCallEndEvent 累计 input/output token，超预算后注入 HintBlock 并把 tool_choice 设置为 none，让 Agent 收尾。更高层还要限制 RAG top_k、工具输出、多 Agent worker 数、fallback/retry 次数，并按 user/org 归因。
```

### Q13：怎么测试这个系统？

标准答案：

```text
测试要覆盖异步风险：用 asyncio.Event 控制 race，测 CancelledError 和 finally；用 fake bus/storage 测 MessageBus 和 service；用 lease 测 RAG worker 丢锁；用 Playwright mock SSE 测前端状态机；用故障注入测重复投递、断线和 worker 崩溃。
```
