## 一、核心概念

### 1.1 什么是长期记忆？

**长期记忆（Long-term Memory）** 是 AgentScope 中用于**让 Agent 在多次会话之间保留并检索持久化信息**的机制。

与上下文管理（短期记忆）不同，长期记忆：
- **跨会话持久化**：用户偏好、历史决策等信息不会因会话结束而丢失
- **语义检索**：通过向量相似度找到相关记忆，而非全量加载
- **自动提取**：由后端（如 mem0）的 LLM 从对话中自动抽取关键事实

**关键理解** 🔴：
- **中间件驱动**：长期记忆以 `Mem0Middleware` 或 `ReMeMiddleware` 形式集成，零侵入 Agent 代码
- **两种后端选择**：
  - **Mem0**：需要 mem0 服务/SDK，基于 Qdrant 向量库
  - **ReMe** ⚠️：进程内嵌入（无需独立服务），基于文件级存储
- **三种控制模式**：`static_control`（全自动）、`agent_control`（Agent 决策）、`both`（混合）
- **模型适配**：通过 `AgentScopeLLM` / `AgentScopeEmbedding` 适配器，复用已有的 AgentScope 模型
- **命名空间隔离**：
  - Mem0：通过 `user_id` + `agent_id` 实现记忆的作用域隔离
  - ReMe：通过 `session_id`（从 `agent.state.session_id` 读取）隔离

### 1.2 为什么需要长期记忆？

| 需求 | 没有长期记忆 | 有长期记忆 |
|------|-------------|-----------|
| 用户偏好 | 每次会话重新询问 | 自动记住"用户喜欢简洁回答" |
| 历史决策 | 无法追溯 | 检索"上次选择了方案 B，因为..." |
| 个性化 | 所有用户一视同仁 | 根据 user_id 提供定制化服务 |
| 跨会话连续性 | 会话结束即遗忘 | 下次对话自动关联历史信息 |
| 多 Agent 协作 | 各自独立 | 通过 agent_id 隔离/共享记忆 |

**核心矛盾**：
- 上下文窗口有限，无法容纳所有历史信息
- 用户期望 Agent "记住"重要信息

**AgentScope 的解法**：中间件 + mem0 后端 + 语义检索

---

### 1.3 长期记忆 vs RAG vs 上下文管理

| 维度 | 长期记忆 | RAG | 上下文管理 |
|------|---------|-----|-----------|
| **数据来源** | 对话中自动提取 | 外部文档（PDF/文本） | 当前会话消息 |
| **生命周期** | 跨会话持久化 | 持久化（直到删除） | 单次会话 |
| **粒度** | 事实/偏好/决策 | 文档片段 | 完整消息 |
| **写入方式** | 自动提取 / Agent 主动 | 手动上传文档 | 自动累积 |
| **检索触发** | 每次 reply / Agent 决策 | 每次 reply / Agent 决策 | 上下文压缩时 |
| **隔离维度** | user_id + agent_id | collection + metadata_filter | 无（会话内共享） |

### 3.2 关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 中间件集成 | `Mem0Middleware` 继承 `MiddlewareBase` | 零侵入，可与其他中间件组合 |
| 三种控制模式 | static / agent / both | 适应不同场景：简单问答 vs 复杂推理 |
| 模型适配 | `AgentScopeLLM` / `AgentScopeEmbedding` | 复用已有模型，避免重复配置 |
| 同步-异步桥 | `_AsyncBridge`（独立线程 + 事件循环） | mem0 接口是同步，AgentScope 是异步 |
| 两级写入降级 | 先 LLM 提取 → 失败则 `infer=False` 直存 | 保证 `add_memory` 一定持久化内容 |
| 记忆注入位置 | `ReplyStartEvent` 后紧跟用户消息 | 与 v1 行为一致，确保模型看到记忆 |
| 工具自动放行 | `PermissionBehavior.ALLOW` | 记忆工具是 Agent 标准能力，不应每次询问 |
| thinking 不持久化 | 只存 content，thinking 留在对话记录 | 避免 Agent 自我叙述污染记忆库 |

### 4.2 核心类实现

#### 4.2.1 Mem0Middleware 核心实现

```python
class Mem0Middleware(MiddlewareBase):
    """mem0 长期记忆中间件"""

    async def on_reply(self, agent, input_kwargs, next_handler):
        # agent_control 模式：直接透传
        if self._mode == "agent_control":
            async for item in next_handler(**input_kwargs):
                yield item
            return

        # static_control / both 模式：
        # 1. 提取查询文本
        query_text = _extract_query_text(inputs)

        # 2. 检索相关记忆
        memories = []
        if query_text:
            memories = await self._async_search(
                query_text,
                user_id=self._user_id,
                agent_id=self._agent_id if self._scope_search_by_agent else None,
            )

        # 3. 进入 Agent 推理，在 ReplyStartEvent 后注入记忆
        injected = False
        async for item in next_handler(**input_kwargs):
            if not injected and memories and isinstance(item, ReplyStartEvent):
                agent.state.context.append(self._build_memory_message(memories))
                injected = True
            if isinstance(item, Msg) and item.role == "assistant":
                final_msg = item
            yield item

        # 4. 写回新对话（finally 确保即使异常也执行）
        finally:
            if query_text and final_msg:
                await self._dispatch_write(
                    [{"role": "user", "content": query_text},
                     {"role": "assistant", "content": final_msg.get_text_content()}],
                    user_id=self._user_id,
                    agent_id=self._agent_id,
                )

    def _build_memory_message(self, memories: list[str]) -> Msg:
        """将检索到的记忆格式化为 AssistantMsg + HintBlock"""
        bullets = "\n".join(f"- {m}" for m in memories)
        content = f"{self._memory_section_header}\n{self._memory_section_intro}\n{bullets}"
        return AssistantMsg(name="memory", content=[HintBlock(hint=content)])
```

#### 4.2.2 AgentScope 适配器实现

```python
class _AsyncBridge:
    """同步-异步桥：在独立线程运行事件循环"""
    def __init__(self):
        self._loop = asyncio.new_event_loop()
        self._thread = threading.Thread(target=self._loop.run_forever, daemon=True)
        self._thread.start()

    def run(self, coro):
        """提交协程到桥接循环，阻塞等待结果"""
        return asyncio.run_coroutine_threadsafe(coro, self._loop).result()


class AgentScopeLLM(LLMBase):
    """mem0 LLM 适配器：将 mem0 的同步调用转为 AgentScope 异步调用"""
    def generate_response(self, messages, ...):
        as_messages = _convert_messages_to_agentscope(messages)  # OpenAI → AgentScope
        response = self._bridge.run(
            _await_chat(self._agentscope_model, as_messages, tools)
        )
        return _parse_chat_response(response, has_tool=bool(tools))


class AgentScopeEmbedding(EmbeddingBase):
    """mem0 Embedding 适配器"""
    def embed(self, text, ...):
        text_list = [text] if isinstance(text, str) else list(text)
        response = self._bridge.run(self._agentscope_model(text_list))
        return response.embeddings[0]  # mem0 期望单个向量
```

#### 4.2.3 两级写入降级策略

```python
async def _async_add_with_fallback(self, text, *, user_id, agent_id):
    """两级写入：先 LLM 提取，失败则直存"""

    # 第 1 级：让 mem0 的 LLM 提取关键事实
    result = await self._async_add(
        [{"role": "user", "content": text, "name": "user"}],
        user_id=user_id, agent_id=agent_id,
    )
    if _mem0_extracted_anything(result):
        return result  # 提取成功

    # 第 2 级：LLM 认为没有值得记忆的内容，直接存储原文
    return await self._async_add(
        [{"role": "user", "content": text, "name": "user"}],
        user_id=user_id, agent_id=agent_id,
        infer=False,  # 跳过 LLM 提取，直接存储
    )
```

**为什么是两级而非三级？**

> v1 曾有三级降级：(a) user role → (b) assistant role → (c) infer=False。
> 但 mem0 v2.x 重构后，提取 prompt 的选择取决于 `filters` 而非 message role，
> 所以 (b) 切换 role 已无意义（同样的 prompt 会运行）。仅保留 (c) 作为兜底。

#### 4.2.4 记忆工具实现

```python
class _SearchMemoryTool(_Mem0MemoryToolBase):
    """多关键词并发搜索"""
    async def __call__(self, keywords: list[str], limit: int = 5) -> ToolChunk:
        # 每个关键词独立查询，并发执行
        per_keyword = await asyncio.gather(*[
            self._mw._async_search(kw, user_id=user_id, agent_id=agent_id, top_k=limit)
            for kw in keywords
        ])
        # 合并去重
        seen, merged = set(), []
        for results in per_keyword:
            for r in results:
                if r not in seen:
                    seen.add(r)
                    merged.append(r)
        return _text_chunk("\n".join(f"- {m}" for m in merged))


class _AddMemoryTool(_Mem0MemoryToolBase):
    """写入记忆：thinking 不持久化，只存 content"""
    async def __call__(self, thinking: str, content: list[str]) -> ToolChunk:
        text = "\n".join(content)  # 只拼接 content，thinking 留在对话记录
        result = await self._mw._async_add_with_fallback(text, user_id=..., agent_id=...)
        return _text_chunk(f"Successfully recorded to memory → {result}")
```

```python
class ReMeMiddleware(MiddlewareBase):
    """基于 ReMe 的长期记忆中间件（进程内嵌入，无需独立服务）"""
    
    # 安装：pip install agentscope[reme]
    # ReMe: https://github.com/agentscope-ai/ReMe
    
    def __init__(
        self,
        *,
        chat_model: ChatModelBase | None = None,      # 注入到 ReMe 的 LLM 组件
        embedding_model: EmbeddingModelBase | None = None,  # 启用向量存储（可选）
        mode: Literal["static_control", "agent_control", "both"] = "both",
        top_k: int = 5,
    ):
        # chat_model: 用于 ReMe 的 auto_memory job（LLM 提取关键事实）
        # embedding_model: 用于向量检索（不提供则仅关键词搜索）
        # mode: 控制模式（同 Mem0Middleware）
        # top_k: 检索返回的最大记忆数

    async def on_reply(self, agent, input_kwargs, next_handler):
        # 1. 提取查询文本
        query_text = _extract_query_text(inputs)
        
        # 2. 启动后台检索任务（static_control/both 模式）
        retrieval_task = None
        if query_text and self._mode in ("static_control", "both"):
            retrieval_task = asyncio.create_task(
                self._reme_app.run_job(_SEARCH_JOB, query_text)
            )
        
        # 3. 快照已存在的消息 ID（用于计算增量）
        pre_existing_msg_ids = {id(msg) for msg in agent.state.context}
        
        # 4. 执行 reply 流程
        async for item in next_handler(**input_kwargs):
            yield item
        
        # 5. 计算增量（新消息，排除记忆提示）
        increment = [msg for msg in agent.state.context if id(msg) not in pre_existing_msg_ids]
        
        # 6. 写回新对话（auto_memory job）
        if increment:
            await self._write_back(increment, session_id=agent.state.session_id)

    async def on_reasoning(self, agent, input_kwargs, next_handler):
        # 检查后台检索任务是否完成
        if self._retrieval_task and self._retrieval_task.done():
            memories = self._retrieval_task.result()
            if memories:
                # 注入记忆到 context（作为 AssistantMsg + HintBlock）
                agent.state.context.append(self._build_memory_message(memories))
        
        # 继续推理流程
        async for item in next_handler(**input_kwargs):
            yield item

    async def _write_back(self, increment: list[Msg], session_id: str):
        """写回新对话到 ReMe"""
        # 只有当有真正的用户轮次 + 至少一个非空助手消息时才持久化
        if not self._has_user_turn(increment) or not self._has_assistant_content(increment):
            return
        
        # 调用 ReMe 的 auto_memory job
        await self._reme_app.run_job(
            _AUTO_MEMORY_JOB,
            messages=self._format_messages(increment),
            session_id=session_id,  # 从 agent.state.session_id 读取
        )
```

**ReMe vs Mem0 对比**：

| 维度 | Mem0Middleware | ReMeMiddleware ⚠️ |
|------|---------------|------------------|
| **部署** | 需要 mem0 服务/SDK | 进程内嵌入（无需独立服务） |
| **存储** | Qdrant 向量库 | 文件级存储 |
| **写入** | 对话后 LLM 提取 | `auto_memory` job |
| **作用域** | `user_id` + `agent_id` | `session_id`（从 agent.state 读取） |
| **检索注入** | `on_reasoning` 同步 | `on_reply` 并发（best-effort） |
| **手动添加工具** | ✅ `_AddMemoryTool` | ❌ 无（写入全自动） |
| **安装** | `pip install agentscope[mem0]` | `pip install agentscope[reme]` |

**设计要点**：
- **进程内嵌入**：ReMe 应用直接嵌入到 AgentScope 进程中，无需启动独立服务
- **并发检索**：检索任务与 reply 并发执行，best-effort 注入（单次 reply 可能在检索完成前结束）
- **自动写入**：通过 `on_reply` hook 自动触发 `auto_memory` job，无手动添加工具
- **session_id 隔离**：作用域按 `session_id` 隔离，从 `agent.state.session_id` 实时读取

### 4.4.1 v2.0.6：Agent Service 内激活 agentic memory（#2263）

**背景**：`AgenticMemoryMiddleware` 是 v2.0.5（#2111）引入的**文件系统型**长期记忆中间件（Markdown 记忆文件 + `DEFAULT_MEMORY_INSTRUCTIONS` 指令），但此前 Agent Service 默认不挂载它——SDK 使用者要自己把它接进 Agent。

**改动**：`create_app()` 的 `extra_agent_middlewares` 工厂签名从三参扩为**四参**：

```python
# 改动前（v2.0.6 之前）
AgentMiddlewareFactory = Callable[
    [str, str, str],                          # (user_id, agent_id, session_id)
    Awaitable[list[MiddlewareBase]],
]

# 改动后（#2263）
AgentMiddlewareFactory = (
    Callable[[str, str, str], Awaitable[list[MiddlewareBase]]]
    | Callable[[str, str, str, WorkspaceBase], Awaitable[list[MiddlewareBase]]]
)
```

**兼容机制** 🔴（关键设计）：`ChatService` 构造时用 `inspect.signature` **探测一次**工厂签名（`_middlewares_take_workspace` 标志），每轮对话按标志决定是否传第 4 参：

```python
# _service/_chat.py — 构造时探测（每 lifespan 一次）
inspect.signature(extra_agent_middlewares).bind("", "", "", None)  # 四参 bind 成功 → True

# 每轮对话按标志传参
factory_args = (user_id, agent_id, session_id)
if self._middlewares_take_workspace:
    factory_args += (workspace,)
middlewares.extend(await self._extra_agent_middlewares(*factory_args))
```

- **旧三参工厂零迁移成本**（探测失败自动回退）
- 探测只做一次（服务每 lifespan 构建一次），**无每轮开销**

**官方示例用法**（`examples/agent_service/main.py`）：

```python
async def longterm_memory_factory(user_id, agent_id, session_id, workspace):
    del user_id, agent_id, session_id
    return [
        AgenticMemoryMiddleware(
            workdir=workspace.workdir,        # 记忆文件存在工作区
            backend=workspace.get_backend(),  # 后端可替换（Local/Docker/...）
        ),
    ]

app = create_app(
    ...,
    extra_agent_middlewares=longterm_memory_factory,
)
```

**为什么"激活"即是增强**：
- `workspace` 参数让记忆中间件**直接读写会话工作区文件系统**——`AgenticMemoryMiddleware(workdir=, backend=)` 的 Markdown 记忆文件落在工作区，经任意后端（Local/Docker/E2B）可达
- 默认 `PER_AGENT` 隔离策略 → **同一 agent 的记忆跨 session 存活**（不同 session 共享工作区记忆），天然满足"长期记忆跨会话"语义

**REST/契约影响**：无端点变化；仅 `extra_agent_middlewares` 工厂契约扩展（向后兼容）。

> - `_AsyncBridge` 提供了一个持久的事件循环

#### Q4: 两级写入降级策略是什么？为什么 v1 是三级而 v2 是两级？（阿里高频）

**参考答案**：
> **两级写入降级策略**：
> ```
> 1. 先调用 mem0.add(infer=True)，让 LLM 提取关键事实
> 2. 若 LLM 认为没有值得记忆的内容（results 为空），则调用 mem0.add(infer=False) 直接存储原文
> ```
>
> **v1 → v2 变化原因**：
>
> | 版本 | 降级策略 | 说明 |
> |------|---------|------|
> | v1 | 三级降级 | (a) user role → (b) assistant role → (c) infer=False |
> | v2 | 两级降级 | (a) infer=True → (b) infer=False |
>
> **为什么 v2 是两级？**
> - mem0 v2.x 重构后，提取 prompt 的选择取决于 `filters`（是否有 `agent_id`），而非 message role
> - 所以 (b) 切换 role 已无意义（同样的 prompt 会运行），仅保留 (c) 作为兜底
>
> **两级降级的优点**：
> 1. 简化逻辑：减少一级降级
> 2. 提高效率：避免无意义的 role 切换
> 3. 保持效果：兜底策略仍然有效

**追问**：
- 两级降级的缺点是什么？→ 如果 LLM 提取失败，只能直存原文
- 如何评估降级效果？→ 记忆质量、召回率
- 有没有其他降级策略？→ 可以使用多个 LLM 模型，选择最好的结果

#### Q8: 如何设计一个支持多租户的长期记忆系统？（阿里高频）

**参考答案**：
> **多租户长期记忆系统设计**：
>
> | 层级 | 隔离方式 | 说明 | 适用场景 |
> |------|---------|------|---------|
> | **user_id 隔离** | 每个租户使用不同的 `user_id` | 记忆天然隔离 | 简单多租户 |
> | **agent_id 细分** | 同一租户的不同业务线使用不同 `agent_id` | 记忆细分 | 复杂多租户 |
> | **scope_search_by_agent** | 控制是否跨 Agent 共享记忆 | 灵活控制 | 通用场景 |
> | **Platform 模式** | 使用 `AsyncMemoryClient` 连接托管服务 | 由 mem0 管理隔离 | 企业级 |
> | **自定义后端** | 实现自己的 mem0 后端，在向量库层做物理隔离 | 完全隔离 | 高安全要求 |
>
> **多租户设计详解**：
> 1. **user_id 隔离**：每个租户使用不同的 `user_id`，记忆天然隔离
>    - 优点：简单，无需额外配置
>    - 缺点：无法细分业务线
> 2. **agent_id 细分**：同一租户的不同业务线使用不同 `agent_id`
>    - 优点：记忆细分，避免混淆
>    - 缺点：需要管理 agent_id
> 3. **scope_search_by_agent**：控制是否跨 Agent 共享记忆
>    - 优点：灵活控制
>    - 缺点：复杂度较高
> 4. **Platform 模式**：使用 `AsyncMemoryClient` 连接托管服务
>    - 优点：由 mem0 管理隔离，无需关心底层
>    - 缺点：依赖第三方服务
> 5. **自定义后端**：实现自己的 mem0 后端，在向量库层做物理隔离
>    - 优点：完全隔离，安全性最高
>    - 缺点：开发成本高
>
> **2026 年趋势**：Platform 模式成为企业级主流

**追问**：

#### Q9: static_control 模式下，记忆会一直留在上下文中吗？如何处理 token 膨胀？（腾讯高频）

**参考答案**：
> **static_control 模式下的 token 膨胀问题**：
> - 记忆以 `AssistantMsg(name="memory")` 形式注入 `agent.state.context`
> - 每次 reply 都会注入新的记忆消息，长期会话会累积
> - 导致 token 膨胀，推理成本增加
>
> **处理 token 膨胀的方法**：
>
> | 方法 | 说明 | 优点 | 缺点 |
> |------|------|------|------|
> | **依赖 `compress_context`** | 上下文压缩时会处理历史消息 | 简单，无需额外配置 | 可能丢失重要记忆 |
> | **手动清理** | 在中间件或 Agent 逻辑中定期 pop 旧的记忆消息 | 灵活控制 | 需要额外逻辑 |
> | **使用 `HintBlock`** | 可被识别和特殊处理 | 未来可扩展 | 当前支持有限 |
> | **记忆去重** | 合并相似的记忆，减少重复 | 减少 token | 可能丢失细节 |
> | **记忆压缩** | 将多条记忆压缩为一条 | 减少 token | 可能丢失信息 |
>
> **2026 年趋势**：记忆去重和压缩成为主流

**追问**：
- 如何评估 token 膨胀？→ 监控 token 消耗，设置阈值
- 记忆去重的风险是什么？→ 可能丢失重要记忆
- 如何避免丢失重要记忆？→ 使用重要性评分，保留重要记忆

#### Q10: 2026 年长期记忆的未来趋势是什么？（阿里高频）

**参考答案**：
> **2026 年长期记忆的四大趋势**：
>
> | 趋势 | 说明 | 影响 |
> |------|------|------|
> | **四层记忆架构** | L0-L3 四层渐进式记忆 | 记忆系统更精细 |
> | **记忆治理** | 准入、更新、清理、合并、删除机制 | 记忆质量提升 |
> | **记忆 vs RAG** | 记忆解决"记不记得"，RAG 解决"知不知道" | 记忆系统更清晰 |
> | **记忆系统方案横评** | Mem0、Zep、Hindsight、Memvid 等方案对比 | 选型更科学 |
>
> **四层记忆架构详解**：
> ```
> L0：原始对话全量保存
>   ↓
> L1：原子记忆（自动提取事实、偏好与关键约束）
>   ↓
> L2：场景分块（按项目聚类实现上下文精准召回）
>   ↓
> L3：用户画像（形成稳定个性化认知）
> ```
>
> **记忆治理详解**：
> - **准入**：只保存稳定、明确、可复用、低风险的信息
> - **更新**：定期更新过期记忆，保持记忆新鲜
> - **清理**：删除无用记忆，减少 token 消耗
> - **合并**：合并相似记忆，减少重复
> - **删除**：删除敏感记忆，保护隐私
>
> **记忆系统方案横评**：
>
> | 方案 | 优点 | 缺点 | 适用场景 |
> |------|------|------|---------|
> | **Mem0** | 易用，开源社区强大 | 缺乏企业治理 | 快速原型 |
> | **Zep** | 异步摘要与抽取 | 学习曲线陡峭 | 对话式 AI |
> | **Hindsight** | 记忆质量高 | 开发成本高 | 高质量场景 |
> | **Memvid** | Token 压缩 | 可能丢失信息 | 成本敏感 |
>
> **2026 → 2028 终局**：
> 记忆将升维为 AI 人格与第三大核心组件，连接身份、历史、偏好与长期关系，使智能体真正成为人类的"第二大脑"。

- 如何选择记忆系统方案？→ 根据场景需求选择

## 八、最佳实践

### 8.1 开发建议

| 建议 | 说明 |
|------|------|
| 优先使用 `both` 模式 | 兼顾自动检索和 Agent 主动操作 |
| 设置合理的 `top_k` | 太多会污染上下文，推荐 3-5 |
| 使用 `threshold` 过滤低质量记忆 | 避免检索到不相关的记忆 |
| `await_write=True` 用于调试 | 确保写入完成，便于排查问题 |
| `await_write=False` 用于生产 | 提升响应速度，写入异步执行 |

### 8.2 性能优化

| 优化点 | 方法 |
|--------|------|
| 并发搜索 | `search_memory` 多关键词并发执行 |
| 后台写入 | `await_write=False` 异步写回 |
| 缓存连接 | mem0 client 复用，避免重复创建 |
| 向量维度匹配 | embedding 模型维度与 Qdrant 配置一致（默认 1536） |

### 8.3 安全建议

| 建议 | 说明 |
|------|------|
| user_id 必须唯一 | 不同用户必须使用不同的 `user_id`，否则记忆会混淆 |
| 审查 `add_memory` 内容 | Agent 可能写入错误信息，建议定期清理 |
| 限制 `top_k` | 避免检索过多记忆导致上下文膨胀 |
| 监控 mem0 调用 | 记忆提取和嵌入会消耗 LLM/embedding 配额 |

## 九、总结

> **一句话总结**：AgentScope 长期记忆是一个基于 mem0 的中间件实现，通过三种控制模式（static_control / agent_control / both）灵活集成到 Agent 推理循环，通过适配器模式复用已有的 AgentScope 模型，通过 user_id + agent_id 实现多层级记忆隔离，并采用两级写入降级策略保证持久化可靠性。
