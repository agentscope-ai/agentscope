## 七、关键设计变化总结

### 7.1 RAG 从 0 到 1
v2.0.3 没有 RAG 模块，v2.0.4 一次性引入了完整的 RAG 管线：
- 文档解析（PDF / Word / Excel / PPT）
- 分块策略（ApproxTokenChunker）
- 三种向量存储后端（Qdrant / Milvus Lite / MongoDB）
- 分布式 & 多租户 RAG 服务

### 7.2 Workspace 沙箱矩阵
从单一 LocalWorkspace 扩展到 6 种后端：
- LocalWorkspace（本地开发）
- DockerWorkspace（容器隔离）
- E2BWorkspace（云端沙箱）
- OpenSandboxWorkspace（远程沙箱）
- K8sWorkspace（集群级，含 MCP 网关）
- Daytona（开发环境）

### 7.3 Agent 中断机制
新增 `UserInterruptEvent`，支持在 ReAct 循环中优雅中断，保存上下文和工具状态，可恢复执行。

### 7.4 长期记忆三选一
- FileBased（内置，零依赖）
- Mem0（向量+图谱混合）
- ReMe（reme-ai 库）

### 7.5 MCP 依赖锁定
MCP SDK 2.0 有 breaking change，当前锁定 `< 2.0.0`，后续需要适配。

## 八、面试关注点

1. **全异步架构**的 trade-off：单进程高并发 vs 调试复杂度
2. **RAG 管线设计**：Parser → Chunker → VectorStore → KnowledgeBase 四层解耦
3. **Workspace 抽象**：BackendBase 统一文件/路径语义，子类只设 workdir
4. **消息总线三模式**：drain queue / replay log / pub-sub，按消费语义分组
5. **MCP 版本锁定**：依赖管理的现实问题，breaking change 应对策略
6. **上下文压缩修复**：多工具调用对的完整性保护

### 9.4 关键设计洞察

1. **结构化输出工具化**：不依赖各厂商 JSON mode，用 tool call 统一实现，与 ReAct 循环融合且验证失败可自我修正
2. **HintBlock 注入 vs 修改系统提示**：动态信息走消息注入以保住 prompt caching 前缀
3. **"摘要即未来唯一历史"**：#2111 压缩 prompt 与 #2134 状态注入形成互补——前者要求摘要自包含，后者在压缩后重新注入时间感
4. **payload + 提升列**：SQL 存储只把过滤字段提升为列，schema 演进无需频繁迁移，与 Redis JSON 策略同构
5. **Hub Con​verge 模式**：用户库 (desired state) ↔ 工作区 (actual state) 收敛机制，与 Kubernetes reconciliation loop 同构——MCPRecord 为期望单源真理，`.mcp` 文件为实际状态，运行时 converge 双向同步
6. **快照模式 + 模板渲染**：安装时从 Hub Card 快照显示字段（离线可用），保留 `values` 于 MCPRecord（升级时预填），不依赖远程可达性

### 11.3 关键设计洞察

1. **Chunker schema 驱动 = 配置随文档走**：#2083 把 chunker 参数从"构造时硬编码"升为"可序列化 schema"，每 KB 持久化 `ChunkerConfig`，索引 worker 按记录重建——不同文档可用不同 chunker/参数，且跨进程可复现，是"配置即数据"的典型实践
2. **中间件吞事件 = 控制流反转**：#2322 让中间件能吞掉 `ReplyEndEvent` 继续循环，配合 `made_progress` 防死循环——把"回复结束"从硬边界变为中间件可干预的软边界，扩展了中间件的表达能力
3. **结构化输出策略阶梯**：#2140 用"原生禁用 → no_think 降级"的能力阶梯，解决 thinking 模式污染结构化输出 + 部分模型拒绝强制 tool_choice 的双重问题
4. **确定性资源释放**：#2349/#2350 流式连接显式关闭，从"依赖 GC 隐式回收"转向"确定性释放"，是高并发下防连接泄漏的工程规范
