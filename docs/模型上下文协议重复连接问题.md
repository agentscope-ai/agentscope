# Bug: MCP list_tools 缺少缓存 + workspace 按 session 重复创建

> 发现日期: 2026-07-05  
> 影响版本: AgentScope 2.x (当前 main 分支)  
> 严重程度: 高（性能退化、对话卡死）

---

## 现象

- 对话极慢或卡住，无明显报错（异常被 `ChatService.run()` 静默吞噬）
- 日志中 `list_raw_tools` 被反复调用，同一 MCP 服务器被连接数十次
- 前端 WebUI 打开 MCP 面板时额外触发连接，加剧问题

## 根因

### Bug 1: `list_raw_tools()` 未检查 `_cached_tools`

**文件**: `src/agentscope/mcp/_mcp_client.py`

`get_tool()` 方法会先检查 `_cached_tools` 是否为 `None`，有缓存则直接使用：

```python
# get_tool() — 正确的缓存检查
if self._cached_tools is None:
    await self.list_raw_tools()
```

但 `list_raw_tools()` 自身**从不检查缓存**，每次调用都发起新的 HTTP 连接：

```python
# list_raw_tools() — 修复前，无脑重连
async def list_raw_tools(self):
    async with self._get_client_gen() as cli:  # ← 每次新建连接
        ...
        self._cached_tools = res.tools        # ← 存了但不检查
```

这导致 ReAct 循环中每轮都重连 MCP 拉工具列表。

**修复**: 在 `list_raw_tools()` 开头加 `if self._cached_tools is not None: return ...`

> 注意：由于 Bug 2（见下），仅修复此 bug 是不够的——不同 session 创建了不同的 `MCPClient` 实例，各自的 `_cached_tools` 互不相通。

### Bug 2: `LocalWorkspaceManager` 按 session 缓存 workspace

**文件**: `src/agentscope/app/workspace_manager/_local_workspace_manager.py`

缓存 key 为 `workspace_id`（每个 session 唯一），同一 agent 的不同 session 创建**不同的** `LocalWorkspace` 对象：

```python
# 修复前
self._cache[workspace_id] = (ws, time.monotonic())
```

对于 E2B/Docker 这是正确的（每个 session 需要独立容器）。但对于 Local 模式：

```python
workdir = os.path.join(self._basedir, agent_id)  # ← 跟 workspace_id 无关
```

同一 agent 的 workdir **完全相同**，应该共享 workspace 对象。

**修复**: 改为 `self._cache[agent_id] = (ws, time.monotonic())`

### Bug 2 扩展: 跨 agent 共享同一 MCP 服务端

即使修复 Bug 2，不同 agent 仍指向不同的 workspace → 不同的 `MCPClient` 实例。当多个 agent 都配置了同一个 MCP 服务器（如 antv-chart），仍会重复连接：

```
agent_sales   → MCPClient_A(antv-chart) → FETCH
agent_admin   → MCPClient_B(antv-chart) → FETCH  ← 不同实例，缓存不共享
agent_finance → MCPClient_C(antv-chart) → FETCH  ← 又重复
```

**修复**: 新增 `_GLOBAL_MCP_CACHE`，key 为 `(url, frozenset(headers))`，跨所有 `MCPClient` 实例共享锁 + 工具列表。

### Bug 3: `streamable_http_client` 未自动发送 Accept 头

**文件**: `mcp` 库（第三方依赖）

Streamable HTTP MCP 协议规范要求客户端发送：
```
Accept: application/json, text/event-stream
```

但 `mcp.client.streamable_http.streamable_http_client` 不会自动添加此头。ModelScope 超时、MinerU 返回 406。

**修复**: 在 `HttpMCPConfig.headers` 中显式添加 `Accept` 头。

## 所有修复清单

| # | 文件 | 改动 | 
|---|------|------|
| 1 | `_mcp_client.py` | `list_raw_tools()` 加 `_cached_tools` 检查 + `asyncio.Lock` | 
| 2 | `_local_workspace_manager.py` | 缓存 key `workspace_id` → `agent_id` | 
| 3 | `_mcp_client.py` | 新增 `_GLOBAL_MCP_CACHE`，跨实例共享 | 
| 4 | `_mcp_client.py` | 新增 `_mcp_cache_key()`，按 URL+headers 标识服务器 | 
| 5 | `_toolkit.py` | MCP `list_tools()` 失败时 try/except + skip 而非崩溃 | 
| 6 | `main.py` (industry_agent) | `HttpMCPConfig.headers` 加 `Accept` 头 | 
| 7 | `_service_chat.py` / `_agent.py` / `_toolkit.py` / `_mcp_client.py` | 关键节点加 INFO 日志 |

## 预期行为（修复后）

- 每个 MCP 服务器在整个进程生命周期内**只连接一次**
- 后续所有 agent、所有 session、所有 ReAct 回合走缓存，0 网络开销
- 单次 MCP `list_tools()` 失败不会崩掉整个对话
