## 一、核心概念

### 1.1 什么是中间件？

**中间件（Middleware）** 是 AgentScope 中用于**在不修改 Agent 或 Model 代码的前提下，向执行流程中的关键位置注入自定义逻辑**的机制。

它可以实现：日志、追踪、输入改写、访问控制、预算限制、TTS 合成等功能。

```
┌─────────────────────────────────────────────────────────────┐
│                    中间件系统全景                              │
│                                                             │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │
│  │  Onion 类    │  │ Transformer  │  │ Tool Source  │      │
│  │  (洋葱式)    │  │  (变换式)    │  │  (工具来源)   │      │
│  └──────────────┘  └──────────────┘  └──────────────┘      │
│                                                             │
│  6 个 Hook 位置 + 1 个 Tool-Provider Hook                   │
│  - on_reply / on_reasoning / on_acting                     │
│  - on_model_call / on_compress_context                      │
│  - on_system_prompt / list_tools                            │
└─────────────────────────────────────────────────────────────┘
```

**关键理解** 🔴：
- **Onion（洋葱式）**：middleware 包裹下一层 handler，可以在 `next_handler()` 前后插入逻辑
- **Transformer（变换式）**：middleware 之间串成流水线，前一个的输出作为后一个的输入
- **Tool source（工具来源）**：不在运行时路径上的 hook，由调用方决定是否调用

---

### 1.2 为什么需要中间件？

| 需求 | 没有中间件 | 有中间件 |
|------|-----------|---------|
| 日志追踪 | 修改核心代码 | 挂载 TracingMiddleware |
| 预算控制 | 硬编码逻辑 | 挂载 ReplyBudgetControlMiddleware |
| TTS 合成 | 修改 Agent 代码 | 挂载 TTSMiddleware |
| 动态上下文 | 改写 system_prompt | 挂载 on_system_prompt middleware |
| 模型回退 | 修改调用逻辑 | 挂载 on_model_call middleware |
| 长期记忆 | 集成到 Agent | 挂载 Mem0Middleware 或 ReMeMiddleware ⚠️ |

**核心矛盾**：
- 核心代码需要**稳定**，不应频繁修改
- 功能扩展需要**灵活**，应可插拔

**AgentScope 的解法**：洋葱模型 + 变换式流水线 + 工具来源

## 二、核心接口

### 2.1 6 个 Hook 位置

| 位置 | 类型 | 说明 |
|------|------|------|
| `on_reply` | Onion | 包裹一次完整的 reply 流程，覆盖所有 ReAct 轮次、工具执行与最终输出 |
| `on_reasoning` | Onion | 包裹一轮 ReAct 中的推理步骤（输入组装 → 模型调用 → 流式解码） |
| `on_acting` | Onion | 包裹一次工具调用的执行 |
| `on_model_call` | Onion | 包裹一次底层 `ChatModel` API 调用，最贴近模型 |
| `on_compress_context` | Onion | 包裹 `Agent.compress_context()` —— 在每次推理步骤前触发 |
| `on_system_prompt` | Transformer | 在每次组装 system prompt 时触发；多个 middleware 串行接力 |
| `list_tools` | Tool source | 可选。返回 middleware 贡献的 `list[ToolBase]`。**不会被自动调用** |

### 2.2 Hook 嵌套关系

```
on_reply
  └── ReAct loop（每一轮）
        ├── on_compress_context（上下文压缩判定）
        ├── on_reasoning
        │     ├── on_system_prompt（组装 system prompt）
        │     └── on_model_call（模型 API 调用）
        └── on_acting（每个工具调用一次）
```

> **注**：当前 `on_acting` 只包裹 agent 运行时内部的工具执行，外部执行的工具不会被追踪。

### 2.3 MiddlewareBase 基类

```python
# src/agentscope/middleware/_base.py:12
class MiddlewareBase:
    """中间件基类"""
    
    def is_implemented(self, hook_name: str) -> bool:
        """检查 hook 方法是否被子类实现"""
        base_method = getattr(MiddlewareBase, hook_name, None)
        sub_method = getattr(type(self), hook_name, None)
        return base_method is not sub_method
    
    # Onion 类 hook
    async def on_reply(self, agent, input_kwargs, next_handler) -> AsyncGenerator: ...
    async def on_reasoning(self, agent, input_kwargs, next_handler) -> AsyncGenerator: ...
    async def on_acting(self, agent, input_kwargs, next_handler) -> AsyncGenerator: ...
    async def on_model_call(self, agent, input_kwargs, next_handler) -> ChatResponse: ...
    async def on_compress_context(self, agent, input_kwargs, next_handler) -> None: ...
    
    # Transformer 类 hook
    async def on_system_prompt(self, agent, current_prompt: str) -> str: ...
    
    # Tool source hook
    async def list_tools(self) -> list[ToolBase]: return []
```

**关键点** ：
- `is_implemented()` 惰性检测：构造时预计算，避免每次循环都检查
- 只需实现需要的 hook，未实现的位置自动跳过
- `input_kwargs` 字典可通过 `next_handler(**input_kwargs)` 透传或覆写

## 三、设计原理

### 3.1 洋葱模型实现

```python
# src/agentscope/agent/_agent.py:538
async def execute_chain(index=0, inputs=inputs):
    if index >= len(self._reply_middlewares):
        # 链尾：调用实际实现
        async for item in self._reply_impl(inputs=inputs):
            yield item
    else:
        mw = self._reply_middlewares[index]
        
        async def next_handler(**kwargs):
            async for item in execute_chain(index + 1, **kwargs):
                yield item
        
        # 调用中间件
        async for item in mw.on_reply(
            agent=self,
            input_kwargs={"inputs": inputs},
            next_handler=next_handler,
        ):
            yield item
```

**执行顺序**：
- **Onion 类 hook**：列表中第一个 middleware 处于**最外层**
  ```
  mw1 前 → mw2 前 → 内部逻辑 → mw2 后 → mw1 后
  ```
  *(流式事件中，内层先 yield 事件)*

- **Transformer 类 hook**：从左到右**串行接力**
  ```
  original_prompt → mw1 → mw2 → final
  ```

---

### 3.2 预分类优化

```python
# src/agentscope/agent/_agent.py:166
# 构造时预分类中间件（性能优化）
self._reply_middlewares = [m for m in middlewares if m.is_implemented("on_reply")]
self._reasoning_middlewares = [m for m in middlewares if m.is_implemented("on_reasoning")]
self._acting_middlewares = [m for m in middlewares if m.is_implemented("on_acting")]
self._model_call_middlewares = [m for m in middlewares if m.is_implemented("on_model_call")]
self._system_prompt_middlewares = [m for m in middlewares if m.is_implemented("on_system_prompt")]
self._compress_context_middlewares = [m for m in middlewares if m.is_implemented("on_compress_context")]
```

**关键点** 🔴：
- 构造时一次性分类，避免每次循环都检查
- 未实现 hook 的 middleware 不会加入对应列表
- 无调用开销

## 四、内置中间件

### 4.1 TracingMiddleware（追踪中间件）

为 agent 全生命周期接入 **OpenTelemetry** 追踪。在 `on_reply`、`on_model_call`、`on_acting` 打点生成嵌套 span。

**配置 TracerProvider**：
```python
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter

provider = TracerProvider()
provider.add_span_processor(
    BatchSpanProcessor(OTLPSpanExporter(endpoint="http://localhost:4318/v1/traces")),
)
trace.set_tracer_provider(provider)
```

> **注**：未配置 `TracerProvider` 时，所有 hook 会直接短路到 `next_handler()`，几乎零开销。

**Span 捕获属性**：
- **Agent Reply Span** (`on_reply`): Agent 名称、session ID、reply ID、输入/输出消息
- **Model Call Span** (`on_model_call`): 模型名、提供商、输入/输出 token 数
- **Tool Execution Span** (`on_acting`): 工具名、调用 ID、入参、执行结果

---

### 4.2 ReplyBudgetControlMiddleware（预算限制中间件）

为**单次 reply** 强制一个加权 token 预算。

**成本计算公式**：`cost = input_token_weight * input_tokens + output_token_weight * output_tokens`

**触发预算上限时的行为**：
1. 在 agent 上下文最后追加 `HintBlock` 提醒模型给出最终结论
2. 将下一步 reasoning 的 `tool_choice` 强制覆写为 `ToolChoice(mode="none")`，阻止继续调用工具

**参数说明**：
| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `token_budget` | float | 必填 | 单次 reply 允许的最大加权 token 成本 |
| `input_token_weight` | float | 1.0 | input tokens 的乘数 |
| `output_token_weight` | float | 1.0 | output tokens 的乘数（通常设得更高以体现成本） |
| `hint_message` | str | 内置收尾 prompt | 预算超出时注入 agent 上下文的提示消息 |

> **注**：该 middleware 实例自身无状态，运行时状态存放在 `agent.state.middle_context` 中，可安全在多个 agent 间共享。预算作用域为**单次 reply**。

---

### 4.3 TTSMiddleware（文本转语音中间件）

拦截 agent 文本输出并合成语音，将音频事件注入事件流。

```python
from agentscope.middleware import TTSMiddleware
from agentscope.tts import DashScopeTTSModel

agent = Agent(
    name="assistant",
    model=model,
    middlewares=[
        TTSMiddleware(
            DashScopeTTSModel(
                credential=DashScopeCredential(api_key="..."),
                model="qwen3-tts-flash",
                parameters=DashScopeTTSModel.Parameters(voice="Cherry"),
                stream=True,
            ),
        ),
    ],
)
```

**TTS 模式适配**：
- **标准模式 (`realtime=False`)**：累积文本直到 `TextBlockEndEvent`，一次性合成完整音频输出
- **实时模式 (`realtime=True`)**：每个 `TextBlockDeltaEvent` 即时推送，音频 chunk 与文本交替并发输出

### 4.4 长期记忆中间件

以中间件形式实现长期记忆，支持两种后端选择：

**Mem0Middleware**（由 mem0 驱动）：
- 挂接 `on_reply`（检索 + 写回）
- 挂接 `on_system_prompt`（声明记忆工具）
- 通过 `list_tools` 提供 `search_memory` / `add_memory` 等工具
- 需要 mem0 服务/SDK，基于 Qdrant 向量库

**⚠️ ReMeMiddleware**（v2.0.4 新增，由 ReMe 驱动）：
- 挂接 `on_reply`（并发检索 + 自动写回）
- 挂接 `on_reasoning`（注入检索结果）
- 通过 `list_tools` 提供 `memory_search` 工具（仅 agent_control/both 模式）
- **进程内嵌入**（无需独立服务），基于文件级存储
- 安装：`pip install agentscope[reme]`
- 详见 `10_长期记忆知识文档.md` 4.2.5 节

## 五、使用示例

### 5.1 计时中间件

```python
import time
from agentscope.middleware import MiddlewareBase

class TimingMiddleware(MiddlewareBase):
    async def on_model_call(self, agent, input_kwargs, next_handler):
        model_name = input_kwargs["current_model"].model
        start = time.time()
        result = await next_handler()
        elapsed = time.time() - start
        print(f"[timing] {agent.name} → {model_name}: {elapsed:.2f}s")
        return result
```

### 5.2 限速中间件

```python
import asyncio
import time
from agentscope.middleware import MiddlewareBase

class RateLimitMiddleware(MiddlewareBase):
    def __init__(self, min_interval: float = 1.0):
        self._last_call = 0.0
        self._min_interval = min_interval

    async def on_model_call(self, agent, input_kwargs, next_handler):
        now = time.time()
        wait = self._min_interval - (now - self._last_call)
        if wait > 0:
            await asyncio.sleep(wait)
        self._last_call = time.time()
        return await next_handler()
```

### 5.4 模型回退中间件

```python
from agentscope.middleware import MiddlewareBase

class ModelFallbackMiddleware(MiddlewareBase):
    def __init__(self, fallback_model):
        self._fallback = fallback_model

    async def on_model_call(self, agent, input_kwargs, next_handler):
        try:
            return await next_handler()
        except Exception as e:
            print(f"Primary model failed: {e}, switching to fallback")
            # 覆写 current_model 参数传递给下一层
            return await next_handler(current_model=self._fallback)
```

### 5.5 全位置覆盖示例

```python
from agentscope.middleware import MiddlewareBase

class FullObservabilityMiddleware(MiddlewareBase):
    async def on_reply(self, agent, input_kwargs, next_handler):
        print(f"[reply] start for {agent.name}")
        async for item in next_handler(**input_kwargs):
            yield item
        print(f"[reply] end for {agent.name}")

    async def on_reasoning(self, agent, input_kwargs, next_handler):
        async for event in next_handler(**input_kwargs):
            yield event

    async def on_model_call(self, agent, input_kwargs, next_handler):
        result = await next_handler(**input_kwargs)
        return result

    async def on_compress_context(self, agent, input_kwargs, next_handler):
        await next_handler(**input_kwargs)

    async def on_system_prompt(self, agent, current_prompt: str) -> str:
        return current_prompt

    async def list_tools(self) -> list:
        return []
```

                  └── [ReAct 循环结束]

#### Q4: 中间件管道（Middleware Pipeline）是如何实现的？

**参考答案**：
> **中间件管道实现**：
> ```python
> # 洋葱模型实现（递归闭包链）
> async def execute_chain(index=0, inputs=inputs):
>     if index >= len(self._reply_middlewares):
>         # 链尾：调用实际实现
>         async for item in self._reply_impl(inputs=inputs):
>             yield item
>     else:
>         mw = self._reply_middlewares[index]
>         
>         async def next_handler(**kwargs):
>             async for item in execute_chain(index + 1, **kwargs):
>                 yield item
>         
>         # 调用中间件
>         async for item in mw.on_reply(
>             agent=self,
>             input_kwargs={"inputs": inputs},
>             next_handler=next_handler,
>         ):
>             yield item
> ```
>
> **关键细节**：
> 1. **递归闭包链**：每个中间件包裹下一层
> 2. **流式支持**：next_handler() 返回 AsyncGenerator
> 3. **参数透传**：input_kwargs 可通过 next_handler(**kwargs) 透传或覆写
> 4. **执行顺序**：第一个中间件处于最外层
>

>         start = time.time()
>         result = await next_handler()  # 调用下一层

>         print(f"[timing] {elapsed:.2f}s")
>         return result
> ```

#### Q5: 预分类优化是如何工作的？如何避免性能瓶颈？

**参考答案**：
> **预分类优化机制**：
> ```python
> # 构造时预分类中间件（性能优化）
> self._reply_middlewares = [m for m in middlewares if m.is_implemented("on_reply")]
> self._reasoning_middlewares = [m for m in middlewares if m.is_implemented("on_reasoning")]
> self._acting_middlewares = [m for m in middlewares if m.is_implemented("on_acting")]
> self._model_call_middlewares = [m for m in middlewares if m.is_implemented("on_model_call")]

> self._compress_context_middlewares = [m for m in middlewares if m.is_implemented("on_compress_context")]
> ```
>
> **is_implemented() 惰性检测**：
> ```python
> def is_implemented(self, hook_name: str) -> bool:
>     """检查 hook 方法是否被子类实现"""
>     base_method = getattr(MiddlewareBase, hook_name, None)
>     sub_method = getattr(type(self), hook_name, None)
>     return base_method is not sub_method
> ```
>
> **性能优化策略**：
>
> | 策略 | 实现方式 | 效果 |
> |------|---------|------|
> | **预分类** | 构造时一次性分类 | 避免每次循环检查 |
> | **惰性检测** | is_implemented() | 未实现的 hook 跳过调用 |
> | **零开销短路** | 未配置时直接跳过 | 几乎零开销 |
> | **无状态设计** | 运行时状态存放在 middle_context | 可安全共享 |
>
> **代码示例**：
> ```python
> class TracingMiddleware(MiddlewareBase):
>     async def on_reply(self, agent, input_kwargs, next_handler):
>         # 未配置 TracerProvider 时直接短路
>         tracer = trace.get_tracer(__name__)
>         if isinstance(tracer, NoOpTracer):
>             async for item in next_handler(**input_kwargs):
>                 yield item
>             return
>         
>         # 配置了 TracerProvider 时打点
>         with tracer.start_as_current_span("agent.reply"):
>             async for item in next_handler(**input_kwargs):
>                 yield item
> ```

#### Q7: 如何处理中间件的一致性问题？（腾讯高频）

**参考答案**：
> **中间件一致性挑战**：
>
> | 问题 | 原因 | 解决方案 |
> |------|------|---------|
> | **顺序冲突** | 多个中间件修改同一数据 | 优先级规则、中间件排序 |
> | **状态不一致** | 中间件状态分散 | 集中状态管理（middle_context） |
> | **异常传播** | 中间件异常影响后续执行 | try-except 包裹、异常隔离 |
> | **性能不一致** | 不同中间件性能差异大 | 预分类优化、零开销短路 |
>
> **解决方案详解**：
>
> **1. 中间件排序**：
> ```python
> # 按优先级排序中间件
> middlewares = sorted(middlewares, key=lambda m: m.priority)
> 
> class MiddlewareBase:
>     priority: int = 100  # 默认优先级
>     
>     def __lt__(self, other):
>         return self.priority < other.priority
> ```
>
> **2. 集中状态管理**：
> ```python
> # 运行时状态存放在 agent.state.middle_context
> class ReplyBudgetControlMiddleware(MiddlewareBase):
>     async def on_reasoning(self, agent, input_kwargs, next_handler):
>         # 从 middle_context 读取状态
>         budget = agent.state.middle_context.get("budget", self.token_budget)
>         
>         # 执行下一层
>         result = await next_handler()
>         
>         # 更新状态
>         agent.state.middle_context["budget"] = budget - result.token_count
>         return result
> ```
>
> **3. 异常隔离**：
> ```python
> class SafeMiddleware(MiddlewareBase):
>     async def on_reply(self, agent, input_kwargs, next_handler):
>         try:
>             async for item in next_handler(**input_kwargs):
>                 yield item
>         except Exception as e:
>             # 异常隔离，不影响后续中间件
>             logger.error(f"Middleware error: {e}")
>             raise
> ```
>
> **2026 年中间件一致性趋势**：
> 1. **优先级规则**：按优先级排序中间件
> 2. **集中状态管理**：middle_context 统一管理状态
> 3. **异常隔离**：try-except 包裹，不影响后续执行

**追问**：

- 如何处理中间件状态不一致？→ 集中状态管理、状态同步机制
- 如何评估一致性的效果？→ 中间件冲突率、状态一致性延迟

> class OptimizedMiddlewarePipeline:
>     def __init__(self, middlewares):
>         # 1. 预分类优化
>         self._reply_middlewares = [
>             m for m in middlewares if m.is_implemented("on_reply")
>         ]
>         
>         # 2. 扁平化（限制数量）
>         if len(self._reply_middlewares) > 5:
>             logger.warning("Too many middlewares, performance may degrade")
>         
>         # 3. 按优先级排序
>         self._reply_middlewares.sort(key=lambda m: m.priority)
>     
>     async def execute_chain(self, index=0, inputs=inputs):
>         # 4. 零开销短路
>         if index >= len(self._reply_middlewares):
>             async for item in self._reply_impl(inputs=inputs):
>                 yield item
>         else:
>             mw = self._reply_middlewares[index]
>             
>             async def next_handler(**kwargs):
>                 async for item in self.execute_chain(index + 1, **kwargs):
>                     yield item
>             
>             async for item in mw.on_reply(
>                 agent=self,
>                 input_kwargs={"inputs": inputs},
>                 next_handler=next_handler,
>             ):
>                 yield item
> ```

## 八、最佳实践

### 8.1 开发建议

1. **只实现需要的 hook**：未实现的 hook 自动跳过，无调用开销
2. **使用预分类优化**：构造时一次性分类，避免每次循环检查
3. **无状态设计**：运行时状态存放在 `agent.state.middle_context` 中
4. **零开销短路**：未配置外部依赖时直接短路到 next_handler

---

### 8.2 性能优化

1. **避免在 hook 中做重计算**：hook 在每次循环中调用
2. **使用惰性检测**：`is_implemented()` 避免重复检查
3. **短路无操作**：未配置外部依赖时直接返回

---

### 8.3 安全建议

1. **不要修改 input_kwargs 中的敏感信息**：除非明确需要
2. **注意 hook 嵌套关系**：on_system_prompt 嵌入在 on_reasoning 内部
3. **list_tools 不会被自动调用**：需要显式收集工具
