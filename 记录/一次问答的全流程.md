前端调用全流程：从发消息到渲染 SSE 事件
一、整体架构：两条独立通道
这是理解整个前端调用的核心——触发和接收是分离的：
┌──────────────────────────────────────────────────────────────┐
│                         前端                                  │
│                                                              │
│   POST /chat/          GET /sessions/{sid}/stream           │
│   (触发通道)            (接收通道 SSE 长连接)                  │
│       │                        │                            │
│       │  fire-and-forget        │  持续接收事件                │
│       ↓                        ↓                            │
│   ┌──────────┐            ┌──────────┐                       │
│   │ChatRun   │            │ SSE      │                       │
│   │Registry  │            │ Stream   │                       │
│   │(spawn)   │            │ (replay  │                       │
│   └────┬─────┘            │  +live)  │                       │
│        │                  └────▲─────┘                       │
│        ↓                       │                             │
│   ┌────────────────────────────┼─────────┐                  │
│   │         MessageBus         │         │                  │
│   │   (Redis Pub/Sub +         │         │                  │
│   │    Replay Log)             │         │                  │
│   └────────────────────────────┴─────────┘                  │
│        │                       ↑                             │
│        ↓                       │                             │
│   ┌────────────┐          ┌──────────────┐                   │
│   │ ChatService│          │  Redis       │                   │
│   │ .run()     │──event──│  Pub/Sub      │                   │
│   │            │          │  channel      │                   │
│   │ agent.     │          └──────────────┘                   │
│   │ reply_     │                                             │
│   │ stream()  │                                             │
│   └────────────┘                                             │
└──────────────────────────────────────────────────────────────┘
POST /chat/ 只返回 {status: "started"}，不返回任何事件。所有事件通过 GET /sessions/{sid}/stream 的 SSE 长连接推送。

Agent 和 Session 的关系
Agent (配置：是谁、怎么思考)
  │
  ├── Session 1 (会话：对话历史 + 运行状态)
  │     └── Chat Run (一次回复执行)
  │
  ├── Session 2 (同一个 Agent 可以有多个会话)
  │
  └── Session 3
Agent 是配置（name、system_prompt、react_config），创建后基本不变
Session 是运行实例（绑定模型配置、工作空间、对话历史），每个 (user_id, agent_id, workspace_id) 三元组唯一
同一个 Agent 可以开多个 Session（不同模型、不同工作空间）

            user_id=user_id,

    raise HTTPException(
        status_code=status.HTTP_409_CONFLICT,
        detail=str(e),
    ) from e

return ChatTriggerResponse(
    status="started",
    session_id=request.session_id,
)

关键点：
chat_service.run() 被 spawn 为后台 asyncio.Task，立即返回
ChatRunRegistry 强制单 session 单 run，第二次 POST 返回 409
响应体不含任何事件，事件通过 SSE 推送

Step 3: ChatService.run() —— 后台执行
# _chat.py (ChatService.run → _run_impl)
async def run(self, user_id, session_id, agent_id, input_msg):
    async with self._message_bus.acquire_lock(
        lock_key, ttl_secs=MessageBusKeys.SESSION_RUN_TTL_SECS,
    ):
        await self._run_impl(user_id, session_id, agent_id, input_msg)

Step 3: ChatService.run() —— 后台执行
_run_impl 内部流程：
  │
  ├── 4a. 加载 session 记录
  │     storage.get_session(user_id, agent_id, session_id)
  │     → SessionRecord (含 config: chat_model_config, state: AgentState)
  │
  ├── 4b. 校验 chat_model_config
  │     如果为 None → 抛异常（需要先 PATCH session 配置模型）
  │
  ├── 4c. 构建 Agent 实例
  │     从 AgentRecord 加载 name, system_prompt, context_config, react_config
  │     从 session.config 加载 chat_model_config, toolkit, middleware
  │     从 session.state 加载对话历史（context, tool_context, tasks_context）
  │     → 实例化 Agent
  │
  ├── 4d. 持久化用户消息
  │     for msg in input_msgs:
  │         await storage.upsert_message(user_id, session_id, msg)
  │
  ├── 4e. 驱动 Agent，逐事件发布
  │     async for event in agent.reply_stream(inputs=input_msg):
  │         ├── 追加到 reply_msg（内存中构建最终消息）
  │         ├── 发布到 MessageBus → Redis Pub/Sub
  │         │     → SSE 连接的 feeder 读取 → 推给前端
  │         └── 投射到其他会话（如 leader 的 HITL 视图）
  │
  └── 4f. finally: 持久化
        ├── upsert_message(reply_msg)    # 保存助手回复
        ├── update_session_state(state)  # 更新会话状态
        ├── log_trim(events_key)         # 裁剪事件日志
        └── 释放锁
