# AgentScope 共享 PVC 模式 — 内网 K8s 部署指南

## 前置条件

- 内网 K8s 集群已就绪（版本 ≥ 1.25）
- 内网私有镜像仓库可用（如 Harbor）
- 集群具备 **ReadWriteMany** 存储类（如 NFS-ClientProvisioner、CephFS），或接受将 agent PVC 降级为 ReadWriteOnce
- `kubectl` 可正常连接集群，且已配置 namespace 管理员权限

---

## 一、镜像准备

### 1.1 所需镜像清单

| 镜像 | 大小 | 说明 |
|------|------|------|
| `agentscope-service:latest` | ~1.97 GB | 主服务（含 kubernetes-asyncio） |
| `agentscope-k8s-workspace:latest` | ~389 MB | 沙箱 Pod（预装 gateway venv） |
| `webui-backend:dev` | ~2.47 GB | Web UI 后端 |
| `webui-frontend:dev` | ~4.74 GB | Web UI 前端 |
| `nginx:alpine` | ~130 MB | 反向代理 |
| `redis:7-bookworm` | ~240 MB | 消息总线 / 缓存 |

### 1.2 导出镜像（本机执行）

```bash
docker save agentscope-service:latest agentscope-k8s-workspace:latest \
  webui-backend:dev webui-frontend:dev nginx:alpine redis:7-bookworm \
  -o agentscope-images.tar
```

### 1.3 内网加载并推送

```bash
# 加载镜像
docker load -i agentscope-images.tar

# 打标签 + 推送到私有仓库
REGISTRY=registry.internal.com/agentscope

docker tag agentscope-service:latest       $REGISTRY/service:latest
docker tag agentscope-k8s-workspace:latest $REGISTRY/k8s-workspace:latest
docker tag webui-backend:dev               $REGISTRY/webui-backend:dev
docker tag webui-frontend:dev              $REGISTRY/webui-frontend:dev
docker tag nginx:alpine                    $REGISTRY/nginx:alpine
docker tag redis:7-bookworm                $REGISTRY/redis:7-bookworm

docker push $REGISTRY/service:latest
docker push $REGISTRY/k8s-workspace:latest
docker push $REGISTRY/webui-backend:dev
docker push $REGISTRY/webui-frontend:dev
docker push $REGISTRY/nginx:alpine
docker push $REGISTRY/redis:7-bookworm
```

## 二、K8s 集群准备

### 2.1 创建命名空间

```bash
kubectl create namespace agentscope
```

### 2.2 确认 StorageClass

Agent PVC 需要 **ReadWriteMany**，查看集群可用存储类：

```bash
kubectl get sc
```

- 如有 `nfs-client`、`cephfs` 等 RWX 类 → 在 `.env` 中设置 `ADP_K8S_STORAGE_CLASS=<名称>`
- 如无 RWX → 将 `ADP_K8S_AGENT_PVC_ACCESS_MODE` 改为 `ReadWriteOnce`（限制：同一 agent 的多 session Pod 须调度到同一节点）

### 2.3 RBAC 权限

service Pod 需要对 `agentscope` namespace 的 Pod 和 PVC 有完整管理权限。如使用默认 ServiceAccount，授予权限：

```bash
kubectl create role agentscope-manager \
  --verb=create,delete,get,list,watch,patch,update \
  --resource=pods,persistentvolumeclaims \
  -n agentscope

kubectl create rolebinding agentscope-manager-binding \
  --role=agentscope-manager \
  --serviceaccount=agentscope:default \
  -n agentscope
```

### 2.4 kubeconfig

将集群的 kubeconfig 文件复制到部署服务器，确认 `docker-compose.yml` 中的挂载路径正确。

## 三、配置修改

### 3.1 `.env` 文件

```ini
# ── 必改项 ────────────────────────────────────────────
ADP_K8S_KUBECONFIG=/path/to/kubeconfig              # kubeconfig 挂载路径
ADP_K8S_IMAGE=registry.internal.com/agentscope/k8s-workspace:latest  # 沙箱镜像地址
ADP_K8S_STORAGE_CLASS=nfs-client                    # RWX StorageClass（可选，有则填）
REDIS_HOST=<内网 Redis 地址>
DEEPSEEK_API_KEY=<内网 LLM API Key>

# ── 共享 PVC 模式 ────────────────────────────────────
ADP_K8S_ENABLED=true
ADP_K8S_SHARED_PVC_ENABLED=true
ADP_K8S_SHARED_PVC_ACCESS_MODE=ReadWriteMany        # 无 RWX 则改为 ReadWriteOnce

# ── 资源与缓存 ─────────────────────────────────────────
ADP_K8S_NAMESPACE=agentscope
ADP_K8S_STORAGE_SIZE=10Gi
ADP_K8S_TTL=120                                      # 空闲 2 分钟回收
ADP_K8S_SWEEP_INTERVAL=30                            # 每 30 秒扫描
ADP_K8S_IMAGE_PULL_POLICY=IfNotPresent

# ── 可选 ──────────────────────────────────────────────
ADP_AUDIT_ENABLED=false
ADP_DLP_ENABLED=false
```

### 3.2 `docker-compose.yml` 调整

```yaml
# 生产环境建议去掉源码挂载（热更新用不到）
# 修改 kubeconfig 挂载路径：
volumes:
  - /etc/kubernetes/agentscope-kubeconfig.yaml:/app/kubeconfig/config:ro

# 镜像地址改为私有仓库：
services:
  agentscope-service:
    image: registry.internal.com/agentscope/service:latest
  webui-backend:
    image: registry.internal.com/agentscope/webui-backend:dev
  # ... 其余同理
```

## 六、常见问题

**Q: 没有 RWX StorageClass 怎么办？**

将 `ADP_K8S_AGENT_PVC_ACCESS_MODE` 设为 `ReadWriteOnce`。功能不受影响，但同一 agent 的多个 session Pod 必须调度到同一个节点。

**Q: Pod 一直 Pending？**

```bash
kubectl describe pod -n agentscope <pod-name>
```

常见原因：镜像拉取失败（检查私有仓库地址和认证）、PVC 无法绑定（检查 StorageClass）、资源不足。

**Q: 沙箱内无法访问外网，bootstrap 会失败吗？**

不会。使用了预构建镜像 `agentscope-k8s-workspace:latest`，gateway venv 和脚本已预装，bootstrap 阶段直接跳过。

**Q: 服务重启后 Pod 和 PVC 还在吗？**

服务重启会调用 `close_all()`，所有 Pod + session PVC 会被清理。Agent PVC（含 skills）保留。
